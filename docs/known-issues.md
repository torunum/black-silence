| KNOWN-5 | **Closed by Plan 0C Task 1.** `tests/fidelity.test.ts` used to prove a carve was faithful purely by **source-text comparison** — pull a line range out of the frozen `reference/sonsurum.html`, pull the matching function body out of the ported module, normalize away TS-only syntax, assert the two strings are equal. That only works while ported code moves verbatim, which a later global-to-state migration cannot do by definition. The fix, exactly as recommended below: a **behavioral recorder**. `tests/support/recordingCanvas.ts` is a Proxy-based 2D context stub that logs every method call and every property assignment, in order, instead of no-op'ing them — including a stable, creation-ordered id for gradient objects (`Gradient#1`, ...) wherever one is used as a logged value (e.g. `fillStyle = someGradient`), so a bug that assigns the wrong (but still previously-created) gradient is a visible diff, not two indistinguishable empty Proxies — and a `getContext` boundary entry per canvas, tagged with a creation-ordered canvas id and that canvas's width/height, so canvas *reuse* and a wrong dimension are visible too (the 2D-context recorder alone has no way to see either: reusing one canvas across many textures doesn't change the sequence or arguments of any single draw call, only where they all end up rendered, and width/height are set on the canvas *element*, which the 2D-context recorder never wraps). `tests/support/recordingAudio.ts` is the WebAudio equivalent, logging node creation, connect edges, parameter assignments/automation, and start/stop, with every created node **and every AudioParam** tagged a stable creation-ordered id so two independent sessions building the same graph produce deep-equal logs despite being different objects (an early version only tagged nodes; `audioInit` connects an LFO straight into another oscillator's gain param, which leaked the live param object into the log before this was caught). Both sides of every comparison — the reference chunk (run via `evalReference`'s `vm` sandbox) and the ported module — draw against the same recorder and the logs are asserted equal via `tests/support/expectCallLogEqual.ts`, which finds the first divergent index with a cheap linear scan before falling through to a real `toEqual` on the equal path — a real mismatch on `buildTextures`' ~30,000-entry log made Vitest's default diff printer take on the order of a minute, which discourages re-running the suite on a genuine regression. Because the drawing/synthesis code calls `Math.random()` directly (`noiseFill`) or via `src/utils/math.ts`'s `rnd`/`pick`, `tests/support/seededRandom.ts` installs a deterministic PRNG over the global `Math.random` for the duration of each comparison — critically, the *outer* `Math` object (the one being patched) must be passed into `evalReference`'s sandbox globals, because a `vm` context otherwise gets its own separate realm intrinsics and would silently ignore the seed. The new tests live in `tests/behavior/textures.test.ts` (`buildTextures`; `texFromPx` on a representative sprite across plain, mirrored, headless/`blankTop`, and masked+stumped dismemberment variants; `buildItemTex`) and `tests/behavior/audio.test.ts` (`audioInit`; `blip`/`bang`/`boom`/`growl` each including their default-argument fallback branch; `snarl` across all eleven archetype branches, not a sample); each was sabotage-tested (a colour, a call-order swap, a loop bound, a frequency, a `connect` target, a gradient swap, a canvas-reuse bug, a canvas-dimension bug) and confirmed to fail for the right reason before being trusted — a first review round caught three real blind spots (`blankTop` uncovered, `snarl` only 4/11 archetypes covered, canvas reuse/dimensions invisible) and two latent ones (gradient identity, an audio-session restore that skipped `finally`) by mutating real source and watching the suite stay green; all five are fixed and re-proven above. The now-redundant byte-identity tests for those specific functions were removed from `tests/fidelity.test.ts`; every data comparison (`PXDEF`, `ENEMY_DEFS`, `WEAPON_STATS`, `MONOLOGUE`, the level grids) and every byte-identity test for a function the recorder does *not* exercise (`buildSprites`, `click`, `noiseBuf`, `gurgle`, `pain`, `deathCry`, `wetDoor`, `stoneDoor`, `bellToll`, `organChord`, `pianoNote`, `startBossMusic`, `stopBossMusic`) were deliberately kept. **What the recorder still cannot reach**, stated plainly rather than claimed away: (1) `buildSprites`' own dismemberment region arithmetic (`armTop`, `armBot`, the mask rectangles) decides *what* to pass to `texFromPx` but issues no draw call itself, so a recorder watching `texFromPx` can't see a regression in that math — it stays guarded by a normalized-source-text test. (2) The eleven Voice/Ambient/Sfx functions listed above have no recorder at all, only the original byte-identity guard — a future task extending `tests/behavior/audio.test.ts` to them would let those retire too. (3) Raw per-sample buffer fills (`noiseBuf`/`bang`/`boom`'s `d[i]=Math.random()*2-1` loops) are plain typed-array writes, not method calls, so the recorder is blind to a change in the *fill formula* itself — only to a change in the buffer's create-call arguments (length, sample rate). (4) Beyond `snarl` (now exhaustive across all eleven branches) and the default-argument branches called out above, the other functions still only cover the specific call/argument combinations each test chose (`blip`'s square-vs-sine/lowpass branch, `bang`'s highpass-vs-not, `texFromPx`'s mirror/masks/blankTop/stumps variants) — not exhaustive over every possible argument. (5) As always, this is a call-log comparison, not a pixel or audio-sample comparison — it proves the same sequence of drawing/synthesis operations happened with the same arguments, not that the rendered pixels or audible sound are perceptually anything in particular (no oracle in this suite has ever verified that). | Closed — Plan 0C Task 1 |
