# Known Issues

Problems found during the port. Phase 0 preserves them deliberately — see the
non-goals in the Phase 0 spec. Each entry names the phase that owns the fix.

| ID | Issue | Owner |
|---|---|---|
| KNOWN-1 | Level 1 places a red key (`K`) and a Guardian miniboss guarding it, but the level contains no locked door (`D`) anywhere. The key is decorative. | Phase 4 — level rebuild |
| KNOWN-2 | `Context` is a service locator, used to make the mechanical port safe. Systems reach into each other through it instead of using `Events`. Each later phase migrates the systems it touches. | Phases 1–5 |
| KNOWN-3 | 17 non-gameplay `setTimeout` calls remain after Plan 0D. They must be cancelled on level unload. | Plan 0D |
| KNOWN-4 | In `loadLevel` (`src/legacy.js`, the `else if(EDEF[ch])spawnEnemy(...)` / `else if("xTCFVO".includes(ch))spawnProp(...)` dispatch), the enemy check runs *before* the prop check. Two characters exist in both `ENEMY_DEFS` and the prop set `"xTCFVO"`: `C` (Cacodemon enemy vs. "chair" prop) and `V` (THE FACTORY FOREMAN boss — 2600 hp, boss bar, 34 melee — vs. "pew" prop). Because enemy wins the dispatch, every `C`/`V` tile in a level grid spawns the enemy, never the prop. Concretely, `src/world/levels/level2.ts` has 8 `V` tiles (written under a "nave pews + altar + boss + cross launcher" comment, intended as pews) and 1 `C` tile (intended as a chair in the priest's chambers) — so Level 2 spawns eight Factory Foreman bosses and a Cacodemon that the level's own comments describe as furniture. (The `C` tiles in levels 6 and 7 are *not* affected by this issue — their comments confirm they are intentional Cacodemons.) This must not be casually "fixed": removing eight bosses from Level 2 is a major balance change, forbidden in Phase 0, and any fix requires deciding what Level 2's furniture should look like instead — a level design decision. Pinned by a characterization test in `tests/world/levels.test.ts`. Also see that test file for a note on `src/world/levels/index.ts`'s grid-legend docstring, inherited from the reference and inaccurate (omits `0`, `7`, `8`, `9`, which do appear in grids). | Phase 4 — level rebuild |
| KNOWN-5 | `tests/fidelity.test.ts` and its `tests/support/` helpers (the "fidelity oracle" built in Plan 0B) prove a carve is faithful by **source-text comparison**: they pull a line range out of the frozen `reference/sonsurum.html`, pull the matching function body or object literal out of the ported module, normalize away the TS-only syntax the port necessarily adds, and assert the two strings (or the two evaluated data literals) are equal. This works only while ported code moves **verbatim** — same statements, same order, same identifiers, modulo the narrow, documented normalizations in `tests/support/normalizeTsSource.ts`. Plan 0C's global-to-state migration rewrites every global read and write it touches — turning bare `AC`/`masterG`-style globals and top-level `let`s into state reads/writes through some other mechanism is *by definition* not verbatim, the same way Plan 0B's own audio accessors (`ctx()`/`masterBus()`/`echoBus()`) already needed a hand-written, per-body `denormalizeAudioAccessors` reversal bolted onto the oracle just to keep comparing two bodies that differ by one mechanical substitution. A whole-codebase migration in that shape is not something a text-diff oracle can be patched to cover — the mechanism this branch spent its effort building cannot guard the plan that most needs guarding. Plan 0D's Three.js upgrade then removes what little would still apply: byte/text identity is *today* the only thing standing between "the art and sound are untouched" and a silent regression (see `noiseFill`, `makeTex`, `texFromPx`, `buildSprites`, `buildItemTex`, and the audio synthesis bodies in `AudioEngine`/`Sfx`/`Voice`/`Ambient`, all guarded this way), and an upgraded rendering API invalidates the reference text's own drawing/API calls, not just the port's. Recommendation (endorsed by the branch's final review): before Plan 0C starts, replace text comparison with **behavioral recording** — a canvas 2D context stub that logs the ordered sequence of draw calls and their arguments instead of no-op'ing them (extending `tests/support/domStubs.ts`'s `make2dContext`), run once against the reference chunk and once against the module, then diff the two call logs. A recording-based oracle survives exactly the kind of refactor a text-diff oracle cannot (reordered locals, renamed accessors, control-flow rewritten around a state object) because it only cares what got *drawn*, not how the code that drew it is shaped. It would also retroactively close a real gap in today's coverage: `noiseFill`, `makeTex`, and the eight `WEAPONS[].snd` closures (stripped out of every `WEAPON_STATS` comparison in `tests/fidelity.test.ts` today, `snd, ...rest`) are never reached by any current oracle entry, since none of today's checks execute a draw/sound call and inspect what it did — only that the source text matches. The audio equivalent is a recording `AudioContext`/`AudioNode` stub that logs the constructed node graph shape and each node's parameter values (frequency, gain, filter type/Q, oscillator type) rather than connection no-ops, diffed the same way. | Plan 0C |
